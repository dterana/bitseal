Encrypt a folder. Open it safely, years later.

One command turns a directory into a single encrypted file. Extraction only happens after the whole file authenticates, and the format version is written into every file, so old ones keep opening.

$ go install github.com/dterana/casemate/cmd/casemate@latest

The first byte is the version. A reader picks its decoder from that byte alone, and refuses anything it does not know.

Unpacking is where tools get hurt.

An archive you did not make can name paths outside the target, carry links, or arrive half corrupted. casemate decrypt -extract assumes the worst.

Nothing until it is verified

Files go into a hidden staging directory. It is renamed into place only after every byte authenticated, and removed on any failure, including Ctrl+C. A wrong password leaves nothing behind.

Hostile entries refused

Absolute paths, .., links, devices and duplicate names are rejected. The extraction path is fuzzed.

Never merges, never overwrites

The destination must not exist. The extracted folder is created with mode 0700.

One byte decides how a file is read.

Most tools quietly change their defaults between releases, and last year's backup stops decrypting. Casemate keeps every format it has ever written and picks the right one from the first byte of the file.

Old files keep opening

Golden test vectors for every shipped version run in CI. A change that breaks an old file fails the build.

New versions are cheap

A format is one file that registers itself. The manager and CLI never change when a version is added.

Upgrades are explicit

casemate rekey moves a file to the current format in place, atomically, when you choose to.

Anatomy of an encrypted file

From password to encrypted file.

Your password is stretched into a key that is slow to guess, then the file is encrypted in authenticated chunks, so large files stream with bounded memory.

Gather secrets

A password, plus an optional key file hashed with SHA-256 as a second factor.

Stretch

Argon2id with a random 16 byte salt per file. Costs live in the header.

Chunk

The file is cut into blocks of up to 2c bytes, so memory stays flat.

Encrypt

Each chunk gets AES-256-GCM with its own nonce and an authentication tag.

Write atomically

Output goes to a temp file and is renamed on success. A crash never leaves half a file.

Made for scripts and pipes.

Data goes to stdout. Prompts and errors go to stderr. Exit codes are real. Passwords can come from a prompt, a file, an environment variable, a file descriptor or a pipe. Add -strict in CI to turn the weak-password and loose-file warnings into errors.

The specifics.

Cipher
AES-256-GCM, authenticated per chunk, so tampering is detected.
Key derivation
Argon2id with a per-file salt. Version 1 files use PBKDF2-SHA256.
Memory
Streaming format. Large files use bounded memory and flow through pipes.
Dependencies
Two direct dependencies, x/crypto and x/term, on top of the Go standard library.
Directories
Encrypted as a tar stream and extracted only after the whole file authenticates. Links and paths that escape the target are refused.
Install
Homebrew, .deb and .rpm packages, release archives with provenance, or go install.
Platforms
Linux and macOS on amd64 and arm64, tested in CI. Windows is not supported for now.
Tests
Unit, CLI, end to end and fuzz tests, plus golden vectors for every format.

Pre-1.0 and not independently audited.

Casemate is young. The format is documented and tested, but it has not had a third-party security review. Read the threat model and the security policy before you rely on it for anything critical.

Verify before you trust it

shasum -a 256 -c checksums.txt --ignore-missing
gh attestation verify casemate_*.tar.gz \
  --repo dterana/casemate

Every archive and package carries signed build provenance, and an SBOM ships with each archive.
